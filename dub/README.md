# ダブ用パレット

英語の動画に日本語の吹き替え音声を乗せるための作業画面。
`/dub/` をブラウザで開くだけで動く。ビルド手順はない。

映像は1フレームも動かせない。だからこの仕事は全部「**固定された秒数の枠に、日本語が入るかどうか**」に潰れる。
この画面がやることも一つだけ。**入らない箇所を、開かずに見つけさせる。**

---

## 壊していない4つ

1. **色は赤だけ。** それ以外は全部グレー
2. **暗いのが道具、白いのが素材**
3. **時間は上から下**
4. **赤はカードを開かずに、位置と件数が分かる**

4 については v0 から増やした。ミニタイムラインを**セル単位**で描くようにしたので、
「このブロックのどこが赤か」まで開かずに分かる。レーンを畳んでも、いちばん下の細い帯に
赤の位置だけは残る。さらに `[` `]` で赤から赤へ飛べる（`赤 3 / 7` と出る）。

---

## 渡し状の6つへの回答

### 1. 空きレーンの余白 ← 一番気にしていたところ

**主因はレーンではなく、コマ撮り画像の大きさだった。**
v0 はコマをカード幅いっぱい・16:9 で置いていた。列幅 530px なら、それだけで298px。
カード1枚が800px近くになり、その高さのぶんだけ隣の列が空く。

コマは**カットを見分けるための見当**であって、見るためのものではない。
96px の見当としてカードの頭に移した。カードの高さがおよそ半分になり、余白もその分減った。

そのうえで残る余白には手を入れた:

- 各レーン列に**縦の罫を1本**通した。空きが「穴」ではなく「休んでいる列」に見える
- 左の時刻レールにも罫と目盛を入れて、目が下りていく筋を作った
- **流し表示**（`F`）を足した。単列・1行の長さを抑えた読み用の並び。列表示は一望と受け渡し用、
  流し表示は90分の読み用、と役割を分けた

正直に言うと、**余白そのものは消えない。**「時間は縦・担当は横」を守る限り、
喋っていない担当の列が空くのは構造的にそうなる。上の3つは、それを穴に見せないための処置。

### 2. カードの中の並び（コマ→原文→訳文→数値）

順番は変えていない。ただし**セルの頭に秒数を出した**。

```
[コマ] [録音] [レーン] [種別]        ← ブロックの頭
       0:18 – 0:29

 1  3.5秒                    0:18    ← 入れ物が先
    So what you're saying is…        ← 原文
    つまりあなたが…                  ← 訳文
    29モーラ 推 8.3/秒 超過+5         ← 判定
```

入れ物（秒数）を知ってから中身を読むほうが順序として正しい。数値は判定なので最後のまま。

### 3. 口合わせカードのセル区切り

罫1本では弱いという指摘のとおりだった。**左に22pxの溝**を作って、そこに
セル番号と縦の罫を通した。**赤いセルは、この溝の罫が赤くなる**ので、
どのセルが入らないのかがカードの端で分かる。

### 4. ミニタイムラインの密度

7px → **8px ＋ 3px の間隔**。加えて:

- **赤は 12px** に伸ばして上下にはみ出させた。灰の中で赤だけが物理的に背が高い
- **10秒ごとの目盛**（50秒ごとは長い）を下に入れた
- レーン略号を左の独立した列に出した（`ナ / A / B`。頭文字がぶつかる組だけ末尾を使う）
- レーンを畳んでも消えない**赤だけの帯**をいちばん下に足した

### 5. 訳文 18px / 太字600 を90分読めるか

**読めるが、重い。** 17px / **500** / 行送り1.85 を既定にした。
600 は日本語の地の文には太い。90分続けるなら、黒みが目に溜まる。

書体は **ヒラギノ角ゴ ProN → 游ゴシック → Noto Sans JP** の順。
どちらも字面が大きくコントラストが低い、長文の地の文に耐える系統。

ただし **明朝も用意した**（ファイル…→書体）。
読み上げる台本を90分読むなら明朝のほうが楽な可能性は高いし、
「暗いのが道具・白いのが素材」の分離も明朝のほうが強く出る。
Windows では細く見えるので、明朝のときだけ太さを600に上げている。
大きさと太さはスライダーで動かせる（ブラウザに憶える）。

### 6. 録音ステータスの四角

塗り／抜きの2値をやめた。**未 / 仮 / 済 の3値**にして、字も入れた。

| | 見え方 |
|---|---|
| **未** | 抜き・薄い罫 |
| **仮** | 斜めのハッチ |
| **済** | 墨べた・白抜き |

形が3段階で変わるので、色を使わずに区別がつく。押すたびに回る（`R` でも回る）。

## v0 から足したもの

### メディアを繋いだ

「音源未接続」だった箇所が本物になった。手元の動画／音声ファイルを選ぶと:

- 再生・シーク・**選択したブロックのループ**（吹き替えの実作業単位）が実際に効く
- 原音オン／オフ ＝ 音量、速度 0.5〜1.25x ＝ `playbackRate`
- **コマ撮り画像が本物になる。** カードが画面に入った順に、そのブロックの開始時刻の
  フレームを切り出す。**灰色で出す** — 実写のフレームに赤が写っていると、
  それだけで警告の赤が薄まるため。確かめたいときはカードに指を置けば色が戻る

ファイルはブラウザの外に出ない。アップロードしていない。

### 本番の録音（WAV）

「録音…」で本番の WAV を読む。**32-bit float** も、24bit PCM も、`bext` 付きの EXTENSIBLE も読める
（RIFF を自前で読んで Web Audio で鳴らす。`<audio>` は float WAV を扱えない環境があるため）。

- カードに**波形の帯**が出る。枠の中は少し濃い地、枠の外は薄い。発声の広がりが下線で出る
- **録音 12.8秒 ／ 枠 12.4秒　はみ出し 後 0.4** のように、枠に対して実録がどう収まっているかが数字で出る
- はみ出していれば、はみ出した部分が赤くなり、カードも赤（＝入らない。推定ではなく実録の赤）
- ピンで囲んだ区間の中なら、枠でなく区間の幅で判定する（モーラの判定と同じ理屈）
- 発声区間は「いちばん重なりの大きい枠」1つに帰属させる。0.2秒はみ出した声を隣で二重に数えない
- 発声の検出は雑音床の4倍（下限 −40 dBFS）。入り 10ms、抜け 250ms の粘り
- 「日本語」（`J`）で録音の入り切り。「原音」（`O`）は映像の音。両方入れれば重なって鳴る
- 映像があれば映像が時計。無ければ録音が時計
- 実測ダイアログの「本番のテイクから足す」に、選択ブロックの録音の秒数が先に入る
- ミニタイムラインの上に、ファイル全体の包絡が一段出る
- メモリ：11分・48kHz・mono の float WAV で 130MB ほど。読んだあと生データは手放し、包絡だけ持つ

編集（ずらす・切る・書き出す）はまだ無い。見えるようにしてから、どう編集したいかを実物で決める。

### 映像の窓

「映像…」で mp4 を読むと右下に窓が出る。「映像」（`V`）でしまえる。コマ撮りはこの映像から取る。

### DAW への橋

「ファイル…→DAW へ」から、ブロックの枠とピンを **Audacity のラベルトラック** または **REAPER のマーカー CSV** で書き出せる。
DAW 側に同じ時刻の目盛が立つので、切り貼りは DAW でやって、収まりの確認はここでやる、という分業ができる。

### 話速の実測（設計メモ D3）

「設定値にすると、一度入れて忘れて実態とずれる」への答え。
スライダーは**仮に動かす道具**であって、基準そのものではない。

1. 原稿を貼る → モーラ数が出る
2. 押して読み始め、読み終わったらもう一度押す。3回
3. **中央値**が基準話速になる。動かせば全セルの赤黒が一斉に塗り替わる
4. 「基準（売り込みのテンション）」と「限界（これ以上は聞き苦しい）」を別々に測る
5. 本番のテイクもデータ点として足せる。入ったテイクの（モーラ数・実秒数）を入れるだけ
6. 外で測った話速（/秒）はそのまま記録できる。**基準には間を含む本番話速、限界には調音速度**を入れる。
   枠は壁時計で決まるので、判定に効くのは間込みの速度。調音速度は「間ゼロでも超えられない天井」

スライダーを動かすと「手で動かした仮値」と表示に出る。実測に戻せる。

### 適合平面（設計メモ 7節・パレットB）

横軸＝持ち時間、縦軸＝モーラ数、実線＝基準話速、破線＝限界話速。
**点が線より上なら赤。線までの縦の距離が、削るべきモーラ数。**
点を押すとそのカードに飛ぶ。下の表は超過の大きい順。

### 文字起こしの取り込み

SRT / VTT を貼ると、**無音閾値のスライダー1本で全ブロックの境界が一斉に切り直る**。
1行ずつ直すのではなく、束ね方をここで決める（設計メモ4節「統一させる層」）。

### 取り込みのやり直し

「ファイル…→レーンを空にする」で、そのレーンのブロックをまとめて消せる。
SRT を間違ったレーンに入れたときはこれで消して入れ直す。
なお「JSON を読み込む」はプロジェクトを丸ごと置き換えるので、正本の JSON があるならそれを読めば済む。

### 保存

正本は JSON 1枚（設計メモ9節）。SRT は出力の一形態にすぎない。
ブラウザに自動保存する（閉じる・隠れる瞬間にも書くので、数百ミリ秒の取りこぼしで原稿を失わない）。
ただし消える場所なので、区切りごとに JSON を書き出すこと。

ファイル画面の「書き出し先フォルダを選ぶ…」で置き場所を固定できる（Chrome / Edge）。
一度選ぶと「JSON を書き出す」はそこへ直接 `<題>.dubproj.json` を書き、自動保存も同じファイルへ 3 秒に 1 回まとめて書き続ける。
Dropbox の中のフォルダ（例：`Dropbox-SFC-CNS/Ryo Murata/CoCdub/JSON`）を選べば、そのまま同期される。
フォルダの記憶はブラウザ側（IndexedDB）に残る。書けないときはダウンロードに切り替わる。

## モーラ計算の限界

漢字のよみは辞書がないと確定しない。ブラウザ単体で `kuromoji.js` の辞書を抱えると重い（設計メモ Q4）。
そこで三段構えにした。

| | 精度 |
|---|---|
| **推定** | 既定。かな1・拗音は前と合わせて1・「っ」「ん」「ー」各1。漢字は熟語1.9/字、単独1.4/字 |
| **読み辞書** | よく出る語を1度登録すれば、以降その語は確定 |
| **よみ欄** | セルごとに「よみ」を押してかなを入れれば、そのセルは確定 |

推定のセルには **推** が付く。pykakasi の実測との差は次のとおり:

```
本ツール  実測   文字列
   19      19   彼は質問を正面から受け止めた
    4       4   シャッター
   13      11   東京特許許可局
   11      11   ファーストインプレッション
   23      21   自分の発言を勝手に言い換えられると
```

**常に多めに出る。** 赤を見逃す側ではなく、余計に赤を出す側に倒れている。
きわどいセルは「よみ」を入れて確定させる。

JSON を書き出して `pykakasi` で数え直し、読み辞書に流し込めば併用もできる。

## キー操作

| | |
|---|---|
| `Space` | 再生 / 停止 |
| `[` `]` | 前の赤 / 次の赤へ飛ぶ |
| `L` | 選択をループ |
| `O` | 原音の入り切り |
| `R` | 録音ステータスを回す |
| `E` | ブロックを編集 |
| `F` | 列表示 ⇄ 流し表示 |

種別のラベル（「口合わせ」など）を押しても、ブロックの編集が開く。
